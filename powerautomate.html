Power Automate Flow 清理作業

依 Creator Object ID 篩選、盤點與後續清理規劃

背景

透過測試用的 Flow「HTTP_JudyTest_Important_NotDelete」，成功取得建立者的 Object ID。這支 Flow 的建立者資訊如下：

CreatorObjectId : 【Judy's Object ID】

若確認這支 Flow 是本人建立的，就可以把這組 ID 視為你的 Creator Object ID。統計結果顯示，此 ID 對應共 115 支 Flow，數量吻合：

115  【Judy's Object ID】

第一階段：設定與篩選

步驟 1 — 設定你的 Object ID 變數：

$myObjectId = "【Judy's Object ID】"

步驟 2 — 只取出你本人建立的 Flow：

$myFlows = $flows | Where-Object {
    $_.CreatedBy.objectId -eq $myObjectId
}

步驟 3 — 確認數量（預期應為 115）：

$myFlows.Count

115

第二階段：整理輸出

完整欄位、依建立時間排序：

$myFlows |
    Select-Object DisplayName,
                  Enabled,
                  CreatedTime,
                  LastModifiedTime,
                  FlowName,
                  EnvironmentName |
    Sort-Object CreatedTime -Descending |
    Format-Table -AutoSize

只看名稱與啟用狀態的簡化版本：

$myFlows |
    Sort-Object DisplayName |
    Select-Object DisplayName, Enabled |
    Format-Table -AutoSize

目前進度

  • 已完成：全公司 Flow → 找到你的 Object ID → 篩選出你建立的 115 支 Flow。
  • 尚未進行：刪除任何 Flow（先不要刪除）。

下一階段：加入執行紀錄

下一步要查詢這 115 支 Flow 的 Run History／最後執行時間，整理成類似下表的格式，才能用「最後執行時間」而非「最後修改時間」來判斷是否為閒置 Flow，準確度會高很多：

Flow NameEnabledLast Run備註
HTTP_JudyTest...True2026/08/30近期有執行
TestABCFalse2025/02/01超過 180 天
Old_Test_FlowFalseNever從未執行過
TestSQLTrue2024/11/20超過 180 天

有了「Last Run」欄位之後，才能安全地找出例如「超過 180 天沒執行」的 Flow，再決定哪些要刪除。

提醒

  • 在確認完整的執行紀錄之前，請勿刪除任何 Flow。
  • 判斷閒置與否，優先使用 Run History 的最後執行時間，而非 LastModifiedTime。
  • 刪除前建議先做一份完整清單備份（含 DisplayName、FlowName、EnvironmentName），以利日後追溯。
